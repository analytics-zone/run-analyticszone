プライバシーを第一に実行する分析: データ、デバイス

プライバシーを損なうことなく、よりスマートにトレーニングできます。ローカル データ処理により、位置情報、健康データ、個人情報を保護しながら、実行中の分析を完全に制御する方法をご覧ください。

重要なポイント

  • データはあなたの人生を明らかにします:実行中のアプリは、GPS 位置情報 (自宅/職場)、健康指標、およびトレーニング パターンを収集し、外出中の状況を明らかにします。
  • クラウドのプライバシー問題:ほとんどのアプリはデータをサーバーにアップロードし、無期限に保存し、サードパーティと共有します。アップロード後は制御できません。
  • プライバシー第一のソリューション:ローカル データ処理により、すべての分析がデバイス上に保持されます。クラウド アップロード、アカウント、追跡は必要ありません。
  • Run Analytics の違い:100% ローカル処理限界走行速度、プロテクト1X/プロテクト2X/プロテクト3X/プロテクト4X、そしてトレーニングゾーン—ランニングデータがiPhoneから外に出ることはありません
  • GDPR 準拠の設計:アプリがデータを収集しない場合、プライバシー法に違反することはできません。プライバシー最優先のアーキテクチャを通じて完全なコンプライアンスを実現します。

ランニングデータはあなたの人生を物語ります。 GPS 追跡により、あなたがどこに住んでいるか、どこで働いているかが明らかになります。トレーニング パターンは、家から離れているときに表示されます。心拍数データにより、フィットネス レベルと健康状態が明らかになります。実行中のほとんどのアプリは、このすべての情報を収集し、クラウド サーバーにアップロードして無期限に保存します。多くの場合、聞いたこともないサードパーティと情報を共有します。

しかし、賢くトレーニングするためにプライバシーを犠牲にする必要はありません。この包括的なガイドでは、人気のランニング アプリに伴うプライバシーの問題を明らかにし、ローカル データ処理がどのように機能するかを説明し、競技ランナーが必要とする高度な指標を提供しながらプライバシー優先のランニング分析がどのように機密情報を保護するかを示します。

ランナーにとってプライバシーが重要な理由

ランニング アプリは必須のトレーニング ツールとなっていますが、そのデータ収集の実践により、ほとんどのランナーが十分に理解していない深刻なプライバシー上の懸念が生じます。カジュアルなアプリの使用とは異なり、分析を実行すると、日常生活、健康状態、行動パターンに関する非常に個人的な情報が明らかになります。

実行中のアプリが収集するデータ

一般的なクラウドベースのランニング アプリを使用すると、単なるワークアウト統計以上のものを提供できます。

⚠️ データ収集の現実:
  • GPS 位置データ:走行ごとに 1 メートルごとに正確な座標を表示し、自宅の住所、勤務先、頻繁に訪れる場所、通常のルートを明らかにします。
  • 時間的パターン:ワークアウトのタイミングには、起床時、仕事中、外出時など、毎日のスケジュールが表示されます。
  • 健康指標:心拍数ゾーン、安静時心拍数、心拍数変動、回復パターンにより、フィットネス レベルと潜在的な病状が明らかになります。
  • パフォーマンスデータ:ペース、距離、高度、ケイデンス、パワーの測定基準により、包括的なフィットネス プロファイルを作成します
  • デバイス情報:電話機のモデル、オペレーティング システム、IP アドレス、および使用パターン
  • 社会情報:名前、電子メール、プロフィール写真、つながり、社会的交流

このデータは単独では存在しません。これらのデータ ポイントを組み合わせると、「今日は 10K を走りました」をはるかに超える、あなたの人生の詳細なプロファイルが作成されます。

データの使用方法

クラウドベースの実行アプリは、トレーニング分析を提供するためだけに大量のデータを収集するわけではありません。あなたの情報には商業的価値があります:

  • サードパーティのデータ共有:多くのアプリは、匿名化された (または匿名化されたと思われる) ワークアウト データを広告主、研究者、データ ブローカーに販売しています。 「匿名化された」位置データであっても、個人を再識別することができます
  • ターゲットを絞った広告:あなたのフィットネス レベル、トレーニング パターン、ランニング目標は、フィットネス製品やサービスであなたをターゲットにするために使用される広告プロファイルに通知されます。
  • 保険リスク評価:健康保険会社はフィットネス データをますます求めています。活動追跡データの共有に「割引」を提供するものもあり、情報を明らかにするよう圧力がかかる
  • 企業情報:集約されたワークアウトデータにより従業員のフィットネスパターンが明らかになり、雇用や健康保険の決定に影響を与える可能性があります
  • 政府の要請:クラウドに保存されたデータは法的手続きに召喚され、位置履歴や行動パターンが明らかになる可能性があります

実際のプライバシーに関するインシデント

プライバシーに関する懸念は理論上のものではなく、文書化されたインシデントとして具体化されています。

ケーススタディ:

Strava ヒート マップ インシデント (2018):Strava の集計されたアクティビティ ヒート マップは、兵士のトレーニングが周囲のパトロール ルートをたどったときに、誤って秘密の軍事基地の位置を明らかにしてしまいました。この事件は、「匿名化された」データによって機密情報がどのように漏洩する可能性があるかを実証しました。

フィットネス アプリのデータ侵害 (2021):大手フィットネス追跡プラットフォームがデータ侵害に見舞われ、数百万のユーザーの GPS 追跡、電子メール アドレス、健康データが流出しました。長年にわたるトレーニング履歴が一般公開されるようになりました。

ロケーションストーキング:セキュリティ研究者は、公開ワークアウト データを使用して、ルートの始点/終点を見つけて自宅の住所を特定する方法を実証しました。これにより、特に一人でトレーニングするランナーにとっては安全上の懸念が生じます。

GDPR 施行措置:欧州のプライバシー規制当局は、不適切な同意メカニズム、過剰なデータ収集、不明確なプライバシーポリシーを理由にフィットネスアプリに罰金を科しており、広範なコンプライアンス違反が浮き彫りになっている。

これらのインシデントは、データをクラウド サーバーにアップロードすると制御を失うという根本的な問題を明らかにします。企業はプライバシー ポリシーを変更したり、違反に見舞われたり、他の企業に買収されたり、政府のデータ要求に直面したりする可能性があり、現在のプライバシー設定に関係なく、履歴データは脆弱なままです。

ローカル処理とクラウド処理を理解する

ローカル データ処理とクラウド データ処理の間でアーキテクチャを選択することにより、プライバシーに関する姿勢が根本的に決まります。この違いを理解すると、機密情報を扱う実行中のどのアプリを信頼するかを情報に基づいて決定するのに役立ちます。

クラウドベースのアプリの仕組み

従来の実行分析プラットフォームは集中型モデルに従っています。

📤 クラウド処理フロー:

  1. データキャプチャ:iPhone または GPS ウォッチは、GPS トラック、心拍数、ペース、ケイデンス、その他のワークアウト指標を記録します。
  2. アップロード:ワークアウトの生データは、インターネット接続経由で会社のサーバーに送信されます。通常はワークアウトごとに自動的に送信されます。
  3. サーバー処理:クラウド インフラストラクチャは分析指標 (rTSS、CTL/ATL、トレーニング ゾーン、パフォーマンス傾向) を計算します。
  4. ストレージ:処理結果と生データは企業サーバーに無期限に残ります (手動で削除しない限り)
  5. 取得:データをサーバーからデバイスまたは Web ブラウザにダウンロードして表示します。

このアーキテクチャは企業に利点をもたらします。一元化されたデータにより、ユーザー集団全体でのソーシャル機能、クロスデバイス同期、機械学習が可能になります。しかし、これはプライバシーに関する重大な弱点を生み出します。つまり、データは企業インフラストラクチャ上で管理外に存在します。

ローカル処理の仕組み

プライバシー最優先のアーキテクチャでは、デバイス上のデータを処理することでこのモデルを逆転させます。

🔒 ローカル処理フロー:

  1. データキャプチャ:Apple Health によってローカルに記録されたワークアウト データ、または GPS ウォッチ ファイルからインポートされたワークアウト データ
  2. ローカルストレージ:データは iPhone の Apple Health データベースに残ります (エンドツーエンド暗号化が有効になっている iCloud を使用する場合は暗号化されます)
  3. オンデバイス処理:分析アプリを実行すると、健康データが読み取られ、計算されますプロテクト0X、プロテクト14X、プロテクト2X/プロテクト3X/プロテクト4X、トレーニングゾーン、およびその他のメトリクスを iPhone のプロセッサーに直接搭載
  4. ローカル結果:計算された指標はデバイスに保存されます。アプリの機能にアップロードは必要ありません
  5. オプションのエクスポート:データをエクスポートするかどうか、いつ、どの形式で、誰が受け取るかを決定するのはあなたです

このアーキテクチャは、アプリがユーザーのデータを決して所有しないことを意味します。アプリはデバイス上にすでに存在する情報を処理し、結果をローカルに保存します。アップロードもクラウドストレージも企業データの所有もありません。

ローカル処理の利点

プライバシー優先のアーキテクチャには、プライバシーだけを超えた利点があります。

🛡️ セキュリティ上の利点

  • 侵害のリスクなし:サーバーに到達しないデータは侵害によって盗まれない
  • 不正アクセス禁止:会社の従業員はあなたのトレーニング履歴を閲覧できません
  • サードパーティとの共有禁止:アプリは所有していないデータを販売できない

⚡ パフォーマンス上のメリット

  • 即時処理:アップロード/ダウンロードの遅延なし - 計算は即座に行われます
  • オフライン機能:完全な分析はインターネット接続なしで機能します
  • 同期の問題はありません:データはいつでもデバイス上で利用可能

✅ コントロールの利点

  • 完全な所有権:削除、エクスポート、共有を制御するのはあなたです
  • アカウントロックインなし:データは独自のクラウド システムに閉じ込められません
  • 真のプライバシー:「あなたのデータを保護することを約束します」ではなく、「私たちがあなたのデータを取得することはありません」

プライバシー最優先のアプローチにより、権力の力関係が変わります。アップロードされたデータの保護を企業に信頼するのではなく、最初から所有権を放棄しないことで完全なコントロールを維持できます。

Run Analytics がプライバシーを保護する方法

Run Analytics は、プライバシー最優先のアーキテクチャをゼロから実装します。あらゆる設計上の決定はデータ保護とユーザー制御を優先し、プライバシーを後付けではなく中核的な機能にします。

100% ローカル データ処理

実行中の分析計算はすべて iPhone 上で行われます。

  • 限界走行速度 (CRS):有酸素性閾値の計算はテストデータを使用してローカルで処理されます
  • トレーニングゾーン:CRS から完全にデバイス上で派生したパーソナライズされた強度ゾーン (ゾーン 1 ～ 7)
  • トレーニング ストレス スコア (rTSS):ローカル CRS 参照を使用して計算されたワークアウト強度の定量化
  • CTL/ATL/TSB トラッキング:ローカルのワークアウト履歴から計算されたパフォーマンス管理チャートの指標 (慢性トレーニング負荷、急性トレーニング負荷、トレーニング ストレス バランス)
  • パフォーマンス指標:VO2max の推定、ペース分析、デバイス上で分析された効率傾向
  • バイオメカニクス解析:ストライド効率、ランニングエコノミー、およびローカルで処理されるフォームメトリクス

計算にはインターネット接続は必要ありません。 Run Analytics サーバーにはデータは送信されません。外部の処理インフラストラクチャがあなたの情報に触れることはありません。

アカウントは必要ありません

Run Analytics は、プライバシーの脆弱性を生み出すアカウント インフラストラクチャ全体を排除します。

🚫 求めていないもの:

  • 登録なし:サインアップフォームや個人情報の収集はありません
  • メールアドレスがありません:私たちはあなたの電子メールを要求したり保存したりすることはありません
  • ログインなし:管理するパスワードや侵害される可能性のあるパスワードはありません
  • プロファイルなし:あなたの情報を含む公開プロフィールまたは非公開プロフィールはありません
  • ユーザー名がありません:完全な匿名性 - あなたが誰であるかわかりません

これは単なる利便性ではなく、プライバシーの保証でもあります。アカウントが存在しない場合、データ侵害によってアカウント情報が漏洩することはありません。 ID を提供しなければ、個人情報の盗難は不可能になります。

第三者による追跡なし

多くの「無料」アプリは、広告ネットワークや分析プラットフォームからの SDK (ソフトウェア開発キット) を追跡することで収益を上げています。これらのサードパーティ ライブラリは、アプリの使用状況を監視し、アプリ間のアクティビティをリンクし、広告プロファイルを構築します。

Run Analytics にはサードパーティによる追跡が含まれていません。

  • 広告なし SDK:Facebook Pixel、Google Analytics、広告ネットワーク トラッカーなし
  • 行動分析なし:Mixpanel、Amplitude、または使用状況追跡サービスはありません
  • クラッシュ報告サービスはありません:デバイス情報を送信するサードパーティのクラッシュ分析はありません
  • ソーシャルメディア統合なし:「Facebook でログイン」またはソーシャル共有 SDK はありません

これは、Apple の Run Analytics のアプリ プライバシー ラベルをチェックすることで確認できます。ラベルには、データ収集カテゴリがまったく示されていません。これは、実行中のアプリでは珍しいことです。

バックアップのためのエンドツーエンド暗号化

Run Analytics データは Apple Health に保存されており、高度なデータ保護を有効にすると、オプションでエンドツーエンド暗号化を使用した iCloud バックアップが提供されます。

🔐 暗号化バックアップ フロー:

  1. ローカル暗号化:健康データは送信前に iPhone 上で暗号化されます
  2. 暗号化された転送:データは暗号化された接続を介して iCloud に送信されます
  3. 暗号化ストレージ:iCloud は暗号化されたデータを保存します - Apple はそれを復号化できません
  4. キーコントロール:資格情報を持つデバイスのみがバックアップを復号化できます

これは、デバイスの移行や冗長化のために iCloud バックアップを使用している場合でも、実行中の分析は非公開のままであることを意味します。Apple は分析にアクセスできず、デバイスのパスコードがなければ政府の要求もできません。

実行中のアプリのプライバシー比較

実行中のすべてのアプリが同じ方法でデータを処理するわけではありません。プラットフォーム間の違いを理解することは、情報に基づいてプライバシーに関する決定を下すのに役立ちます。

Strava: ソーシャルファースト、プライバシー最後

Strava はソーシャル フィットネス トラッキングの先駆者ですが、そのアーキテクチャはプライバシーよりも共有を優先しています。

アスペクトStrava のアプローチプライバシーへの影響
データ処理100% クラウドベースのサーバー処理すべてのワークアウト データはアップロードされ、無期限に保存されます
アカウント要件メールによる登録必須あらゆる活動に関わる個人情報
位置データサーバーに保存された完全な GPS トラック企業がアクセスできる包括的な位置履歴
ソーシャル機能デフォルトのパブリックプロファイル、アクティビティ共有フォロワーにワークアウトが表示されます。オプトアウトには構成が必要です
サードパーティの共有データはパートナーと共有され、研究のために集約されますダウンストリームのデータ使用量に対する制限された制御
プライバシー管理プライバシー ゾーンは開始/終了位置を非表示にします位置情報の漏洩を軽減しますが、排除することはできません

結論:Strava のソーシャル機能には集中化されたクラウド インフラストラクチャが必要であり、真のプライバシーは不可能です。社会的な動機を求める競技ランナーにとっては便利ですが、プライバシー最優先の原則とは相容れません。

Garmin Connect: クラウド依存

Garmin は包括的なトレーニング分析を提供しますが、完全にクラウド処理に依存しています。

  • サーバーの依存関係:すべての高度な分析 (トレーニング ステータス、トレーニング負荷、VO2max トレンド) には Garmin のクラウド プラットフォームが必要です
  • アカウントのロックイン:履歴データは Garmin サーバーのみに保存されます。完全な履歴をエクスポートするのは困難です
  • GPS トラック ストレージ:すべてのワークアウトの GPS データをアップロードして保持
  • サードパーティの統合:Garmin Connect は API 接続を通じて多数のフィットネス プラットフォームとデータを共有します
  • 限られたプライバシー オプション:アクティビティをプライベートに設定できますが、データは引き続き Garmin インフラストラクチャに存在します

結論:Garmin のエコシステムでは、包括的なワークアウト履歴を持つ同社を信頼する必要があります。ローカルのみの分析のオプションはありません。

Runalyze: サーバーベースの処理

Runalyze は高度なトレーニング分析を提供しますが、従来のクラウド アーキテクチャを使用します。

  • アップロードが必要です:すべてのワークアウト ファイル (.fit、.tcx、.gpx) は分析のために Runalyze サーバーにアップロードする必要があります
  • サーバーストレージ:Runalyze インフラストラクチャに保存された完全なワークアウト データベース
  • オープンソースの透明性:コードはオープンソースであるため、プライバシーの検証が可能 - 大きな利点
  • セルフホスティング オプション:上級ユーザーは独自の Runalyze インスタンスをホストして完全なデータ制御を行うことができます
  • 限定的なサードパーティ共有:パートナーシップ/データ共有契約が少なく、より小規模なプラットフォーム

位置情報データの保護

ランニング ワークアウトの GPS 追跡により、生活パターンに関する機密情報を明らかにする包括的な位置履歴が作成されるため、ランナーにとって位置プライバシーは非常に重要になります。

GPS追跡のリスク

GPS で追跡された走行ごとに、次のような詳細な位置履歴が作成されます。

⚠️ 位置データから明らかになること:
  • 自宅住所:毎日同じ場所から始まるランニングで、どこに住んでいるかが特定される
  • 勤務地:ランチタイムのランニングや職場から始まるルートは雇用場所を明らかにします
  • 毎日のルーチン:規則的なルートとタイミングパターンは予測可能な行動習慣を示します
  • 欠勤パターン:自宅でのランニングのギャップは、旅行中または外出中であることを示します
  • 社会的なつながり:他の人と一緒に走ると人間関係や集合場所が明らかになる可能性がある
  • プライベートロケーション:医療施設、礼拝所、その他の機密性の高い目的地

この情報は、特に一人でトレーニングしているランナーにとっては安全上の懸念を引き起こし、また、誰が長年にわたる包括的な運動履歴にアクセスできるのかというプライバシー上の懸念を引き起こします。

プライバシーゾーンと安全性

実行中の一部のアプリは、指定した住所付近の GPS トラックの一部を非表示にする「プライバシー ゾーン」を提供します。

  • 仕組み:機密性の高い場所の周囲に円形のゾーン (通常は半径 200 ～ 500m) を定義します。ゾーン半径内に隠れた GPS トラック
  • 制限事項:データは公開ディスプレイでのみ非表示にします。完全な GPS データは引き続きサーバーにアップロードされ、会社がアクセスできます。
  • 構成の負担:すべての機密性の高い場所を手動で識別して構成する必要がある
  • 偽りのセキュリティ:完全なデータがクラウド ストレージに残りながら、プライバシーの印象を与えます

プライバシー ゾーンは部分的な保護を提供しますが、根本的な問題には対処しません。つまり、GPS データがサーバーにアップロードされると、完全な位置履歴がユーザーの制御外に存在してしまいます。

🗺️ 位置情報のプライバシー機能:

  • 選択的共有:ワークアウト データをエクスポートするときは、GPS トラックを含めるか、概要統計のみをエクスポートするかを選択します。

  • 完全な制御:Apple Health からいつでもワークアウトの場所データを削除 - 削除はすぐに Run Analytics に反映されます

このアーキテクチャは、あなたのロケーション履歴があなたの排他的な制御下に残ることを意味します。特定のワークアウトをコーチと共有したいですか?そのワークアウトだけをエクスポートします。ルートを明らかにせずにトレーニングの傾向を分析したいですか? GPS 座標なしで CSV データをエクスポートします。完全な柔軟性、完全な制御。

GDPR とデータの権利

欧州連合の一般データ保護規則 (GDPR) は包括的なデータ保護の権利を確立しており、他の管轄区域でも同様のプライバシー法が採用されているため、その原則は世界中に適用されます。

GDPR が保証するもの

GDPR は、個人データに対する広範な権利を個人に付与します。

  • アクセスする権利:企業は、あなたに関して保有しているすべてのデータのコピーを提供する必要があります
  • 是正する権利:不正確な個人データを修正する
  • 消去する権利 (「忘れられる権利」):特定の状況下で個人データの削除を要求する
  • データポータビリティの権利:別のサービスに転送するために個人データを機械可読形式で受信します
  • 異議を唱える権利:マーケティング、プロファイリング、または研究目的での処理に反対する
  • 処理を制限する権利:企業によるデータの使用方法を制限する

これらの権利は理論的にはユーザーを保護しますが、その施行は企業のコンプライアンスに依存します。また、権利を行使するには、多くの場合、複雑な手順を実行し、回答を数週間待ち、企業がバックアップを含むすべてのシステムから実際にデータを削除することを信頼する必要があります。

Run Analytics の準拠方法

Run Analytics は、アーキテクチャのシンプルさによって完全な GDPR 準拠を実現します。

📜 プライバシー最優先の設計による GDPR 準拠:

  • データ収集なし = 完全なコンプライアンス:GDPR は個人データの処理を規制します - アプリがデータを収集しない場合、規制は適用されません
  • データ主体のリクエストは不要です:私たちが持っていないデータへのアクセスをリクエストすることはできません。収集していないデータの削除をリクエストすることはできません
  • 同意なしのメカニズム:追跡がない場合、Cookie バナーや同意フォームは必要ありません
  • 違反通知義務なし:私たちが所有していないデータを侵害することはできません
  • 国際転送の心配なし:データはデバイス上に残ります - 国境を越えたデータ転送はありません

これは法的手段によるコンプライアンスではなく、プライバシーの基本的な尊重によるコンプライアンスです。最も安全なデータは、決して収集されないデータです。

権利の行使

クラウドベースで実行中のアプリの場合、GDPR 権利を行使するには通常、以下が必要です。

📋 一般的な GDPR リクエストのプロセス:

  1. リクエストの送信:プライバシー チームに電子メールを送信するか、アカウント設定を使用してデータ アクセス/削除をリクエストします。
  2. 本人確認:本人確認書類の提出（安全のため）
  3. 待機期間:企業は 30 日以内に回答する必要があります (90 日まで延長可能)
  4. レビューの返信:データのエクスポートまたは削除の確認を受け取る
  5. 実際のコンプライアンスの希望:その会社が実際にすべてのシステム、バックアップ、サードパーティ製プロセッサからデータを削除したと信じてください。

Run Analytics を使用すると、このプロセス全体がバイパスされます。データはすでにデバイス上に独占的に存在します。すべて削除したいですか?アプリとApple Healthワークアウトデータを削除します。輸出したいですか？アプリのエクスポート機能をいつでもご利用いただけます。履歴データにアクセスしたいですか?すべてiPhoneにあります。企業に許可を求めることなく、即時かつ完全に制御します。

  • パフォーマンスの傾向:衰退パフォーマンス指標病気、オーバートレーニング、または健康上の問題を示している可能性があります

  • 採用選考：雇用主によっては、特定のポジションに対して適性基準を使用している場合があります。包括的な健康データは雇用の決定に役立つ可能性がある

  • きめ細かな権限:iOS は、各データ タイプ (ワークアウト、心拍数など) に対して明示的な承認を必要とします。Run Analytics がアクセスできる内容を正確に制御します。

  • 健康データの送信なし:心拍数、VO2max の推定値、フィットネス指標が iPhone から離れることはありません

  • 暗号化された iCloud バックアップ:高度なデータ保護を使用すると、医療データはエンドツーエンドの暗号化でバックアップされます。

匿名のランニング分析

分析を実行する際の真の匿名性を実現するには、データ収集および処理チェーンからすべての個人識別子を排除する必要があります。 Run Analytics は、アカウントなしのアーキテクチャを通じてこれを実現します。

アカウントなし、プロフィールなし

実行中のほとんどのアプリは登録から始まり、今後のすべてのアクティビティをユーザーの ID に結び付けるアカウントを作成します。 Run Analytics はこれを完全に排除します。

  • ゼロ登録:App Store からダウンロードしてすぐに使い始めてください。フォームやサインアップのプロセスは必要ありません。
  • 個人情報なし:アプリが名前、メールアドレス、生年月日、性別、その他の個人情報を尋ねることはありません
  • ユーザーIDがありません:セッション間でデータをリンクする内部ユーザー識別番号がない
  • 追跡トークンなし:使用状況追跡のためのデバイスのフィンガープリントや固有の識別子はありません

メールアドレスは不要です

電子メール アドレスは、あなたのアイデンティティとアプリの使用の間に永続的なリンクを作成します。これらにより次のことが可能になります。

  • クロスプラットフォームトラッキング:電子メールアドレスは、広告ネットワークを通じてアプリやウェブサイト全体のアクティビティをリンクします
  • データ ブローカーのマッチング:データ ブローカーはメール関連データを購入してプロフィールを充実させます
  • マーケティングリスト:メールリストが第三者に販売、共有、または漏洩される
  • 侵害の危険性:データ侵害により、ワークアウト データと一緒に電子メール アドレスが公開される

Run Analytics は電子メール アドレスを要求することはありません。そのため、ID のリンク、マーケティング リスト、侵害の危険にさらされることはありません。

完全な匿名性

アカウントなし、追跡なし、ローカル処理の組み合わせにより、真の匿名性が実現されます。

👤 匿名使用の保証:

  • 私たちはあなたのことを知りません:Run Analytics は、誰がアプリを使用しているのか、名前、メールアドレス、識別子をまったく知りません。
  • プロファイルを構築できません:ユーザー ID がなければ、使用状況プロファイルを作成したり、長期にわたる行動を追跡したりすることはできません
  • ハッキングできない:ハッカーは会社のサーバーに存在しないデータを盗むことはできません
  • 召喚状は発行できません:ユーザーデータに対する政府または法的な要求は空の結果を返します - 私たちはそれを持っていません
  • 考えを変えることはできません:ビジネス慣行が変わっても、活用できる履歴データは存在しない

これは、「データをあなたにリンクしません」という匿名性ではなく、「データを持っていないため、データをあなたにリンクすることはできません」という構造的な匿名性です。

プライバシーに関するよくある質問

クラウド AI を使用しないローカル分析はどの程度正確ですか?

精度は場所ではなく方法論に依存します。クラウドベースのアプリは本質的に精度が高いわけではなく、デバイスではなくリモート サーバーでデータを処理するだけです。 Run Analytics は、科学的に検証された同じ処方を使用しています。プロテクト0X、プロテクト14X、そしてトレーニングゾーンクラウドプラットフォームとして。計算は同じです。 iPhone のプロセッサ上で動作するだけです。最新の iPhone は、10 年前のサーバー ファーム全体よりも多くのコンピューティング能力を提供しており、ローカル処理により精度を損なうことなく即座に結果が得られます。

ワークアウトをコーチとプライベートに共有できますか?

はい、共有を制御するのはあなたです。Run Analytics は、柔軟なエクスポート オプションを提供します。個々のワークアウトまたは日付範囲を JSON、CSV、HTML、または PDF 形式でエクスポートします。エクスポートしたファイルを、電子メール、メッセージング アプリ、または選択したクラウド ストレージ経由でコーチに送信します。データが自動的にサーバーに同期されるクラウド プラットフォームとは異なり、何を共有するか、いつ共有するか、誰が受信するかを正確に決定できます。コーチは、トレーニング履歴全体に永続的にアクセスすることなく、分析に必要なワークアウト データを取得します。

デバイスを紛失した場合のバックアップはどうなりますか?

Advanced Data Protection を備えた iCloud Health バックアップを使用します。Apple Health は有効にすると iCloud にバックアップし、デバイスの移行と回復を提供します。 Advanced Data Protection を有効にすると、エンドツーエンドの暗号化が追加されます。Apple は健康データを復号化できず、認証されたデバイスのみが健康データにアクセスできます。新しい iPhone をセットアップし、iCloud バックアップから復元すると、すべての健康データ (Run Analytics で使用されるワークアウト履歴を含む) が自動的に転送されます。これにより、データを第三者に公開することなく冗長性が提供されます。

デバイスを紛失した場合はどうなりますか?

標準の iOS セキュリティがデータを保護します。iPhone は健康情報を含むすべてのデータを暗号化します。デバイスを紛失した場合: (1) Find My iPhone を使用してリモートからデータを消去し、データを完全に消去します。または、(2) デバイスはパスコードでロックされたままになり、権限のないユーザーはデータにアクセスできなくなります。 iCloud ヘルスバックアップを有効にしていた場合、新しいデバイスはすべてのワークアウトデータを復元します。バックアップがなければデータは失われますが、これはプライバシーとのトレードオフです。完全な制御は完全な責任を意味します。冗長性を確保するために、暗号化された iCloud バックアップを有効にすることを検討してください。

外部分析のためにデータをエクスポートできますか?

はい - 複数の形式オプション。Run Analytics は 4 つのエクスポート形式を提供します: (1)プロテクト25Xプログラム分析および開発者ツール用、(2)プロテクト26XExcel/Numbers/Google スプレッドシートでのスプレッドシート分析用、(3)プロテクト27Xチャート付きの読みやすいレポートの場合、および (4)プロテクト28Xコーチの共有または印刷用。特定の日付範囲を選択し、含めるメトリクスを選択し、iOS 共有シートを介して任意の宛先にエクスポートします。データの移植性は維持されます。独自の形式やエクスポート制限はなく、好みの分析ツールに完全に柔軟に対応できます。

スマートにトレーニングするためにプライバシーを犠牲にする必要はありません。最新の iPhone 機能により、ローカル データ処理を通じて高度な実行分析が可能になり、機密情報を独占的に管理しながら、クラウドベースのプラットフォームと同じ高度なメトリクスを提供できます。

プライバシーに関するよくある質問

Run Analytics は本当に非公開ですか?

はい - アーキテクチャ設計を通じて 100% プライベートです。 Run Analytics はすべてのデータを iPhone 上でローカルに処理し、ワークアウト情報、GPS トラック、健康指標を外部サーバーにアップロードすることはありません。このアプリにはアカウントは必要なく、個人情報も収集せず、サードパーティの追跡 SDK も含まれていません。これは、データ収集カテゴリがゼロであることを示す Apple のアプリ プライバシー ラベルをチェックすることで確認できます。これは信頼によるプライバシー (「私たちはあなたのデータを保護することを約束します」) ではなく、アーキテクチャによるプライバシー (「私たちがあなたのデータを保持することはありません」) です。

ローカル処理はどのように機能しますか?

ローカル処理これは、すべての計算がリモート サーバーではなく iPhone のプロセッサ上で行われることを意味します。 Run Analytics は、Apple Health (デバイスにローカルに保存されている) からワークアウト データを読み取り、次の計算を実行します。プロテクト0X、プロテクト14X、プロテクト2X/プロテクト3X/プロテクト4X、そしてトレーニングゾーンiPhone の CPU を使用して、結果をアプリのローカル データベースに保存します。処理のためにデータがインターネット経由で送信されることはありません。最新の iPhone は、クラウドに依存せずに高度な分析を行うのに十分なコンピューティング能力を提供します。アップロード/ダウンロードの遅延がないため、結果は即座に表示されます。

Run Analytics はどのようなデータを収集しますか?

なし。Run Analytics はゼロ データを収集します。アプリは、Apple Health から (明示的な許可を得て) ワークアウト情報を読み取りますが、外部サーバーに送信せずにローカルで処理します。アカウントがないということは、メール アドレスが収集されないということです。追跡 SDK がないということは、行動データが収集されないことを意味します。分析サービスがないということは、使用状況に関する統計がないことを意味します。クラウド処理がないということは、ワークアウトのアップロードがないことを意味します。文字通り、アプリにはデータを収集する技術的能力がありません。データを受信するサーバー エンドポイントがありません。検証のために、App Store のアプリ プライバシー ラベルを確認してください。データ収集カテゴリはゼロです。

Run Analyticsを使用するにはアカウントが必要ですか?

いいえ、アカウントはまったく必要ありません。 App StoreからRun Analyticsをダウンロードして、すぐに使い始めてください。登録フォーム、電子メール認証、パスワードの作成、プロファイルのセットアップは必要ありません。このアプリにはアカウント インフラストラクチャさえありません。ログインするものが何もないため、ログイン画面もありません。これにより、利便性 (即時アクセス) とプライバシー (完全な匿名性) の両方が提供されます。使用状況はデバイスに対して完全にローカルに保たれ、外部システムへの ID リンクはありません。

Run Analytics は私のデータを販売できますか?

不可能です。販売できるデータがありません。Run Analytics は、ワークアウト データ、GPS トラック、健康指標をサーバーにアップロードすることはありません。すべての処理は iPhone 上でローカルに行われます。企業は自社が保有するデータのみを販売できますが、当社はユーザーデータを一切保有していません。ユーザーのワークアウトのデータベース、GPS トラックのサーバー ストレージ、健康情報の収集はありません。このアーキテクチャ上の決定により、ポリシーで禁止されているだけでなく、データ販売が技術的に不可能になります。これは可能な限り最も強力な保証です。私たちは持っていないものを売ることはできません。

私の位置情報データは安全ですか?

はい。位置データは Apple Health 内の iPhone にのみ保存されます。 Run Analytics は、GPS トラックや座標を外部サーバーにアップロードすることはありません。アプリは距離とペースを計算するためにヘルスケアから位置データを（許可を得て）読み取ることができますが、すべての処理はローカルで行われます。 GPS トラックは Apple Health の管理下に残り、iOS 暗号化とアクセス制御によって保護されます。ワークアウト データをエクスポートするときは、位置情報を含めるか、概要統計のみを共有するかを選択します。ローカルのみのアーキテクチャによる完全な位置プライバシー。

iCloudバックアップはどうなるのでしょうか？

iOS 設定でヘルスバックアップを有効にすると、Apple Health データが iCloud にバックアップされます。最大限のプライバシーを確保するには、有効にしてください高度なデータ保護—これにより、ヘルスケアのバックアップにエンドツーエンドの暗号化が追加されます。つまり、Apple はデータを復号化できなくなります (認証されたデバイスのみがデータにアクセスできるようになります)。 iCloud バックアップは、適切に構成されていれば、プライバシーを犠牲にすることなくデバイスの回復と移行を実現します。 Run Analytics データは Apple エコシステムのプライバシー保護内に留まり、個別のクラウド サービスやサードパーティのバックアップ プロバイダーはなく、iOS セキュリティ モデルと完全に統合されています。

Strava との違いは何ですか?

基本的に異なるアーキテクチャ:Strava では、処理のためにすべてのワークアウト データをサーバーにアップロードする必要があります。GPS トラック、心拍数、パフォーマンス メトリックはすべて Strava のクラウド インフラストラクチャに保存されます。 Strava はアカウント登録 (電子メール アドレス) を必要とし、ソーシャル機能 (パブリック プロフィール) を提供し、サードパーティ パートナーとデータを共有します。 Run Analytics はすべてを iPhone 上でローカルに処理し、アカウントを必要とせず、データのアップロードもゼロで、ソーシャル機能も提供しません。 Strava はソーシャルなつながりを優先します。 Run Analytics はプライバシーを優先します。どちらもトレーニング分析を提供しますが、まったく反対のアーキテクチャ アプローチを通じて行われます。私たちのを参照してください詳細な比較上。

プライバシーにより精度が低下しますか?

いいえ、プライバシー最優先のアーキテクチャにより精度が損なわれることはありません。パフォーマンス指標処理場所ではなく、計算方法に依存します。 Run Analytics は、科学的に検証された同じ処方を使用しています。限界走行速度、トレーニングストレススコア、クラウドベースのプラットフォームとしてのトレーニング ゾーン計算。計算はリモート サーバーで実行されるか iPhone で実行されるかに関係なく同じです。ローカル処理はネットワーク遅延なしで即座に行われます。最新の iOS デバイスは、以前はサーバー ファームが必要だった分析に大規模なコンピューティング能力を提供します。ローカル処理により、プライバシーと正確性が完全に共存します。

データをエクスポートできますか?

はい - 完全なエクスポートの柔軟性。 Run Analytics は、複数のエクスポート形式を提供します。プロテクト25X(プログラム分析の場合)、プロテクト26X(スプレッドシートの場合)、プロテクト27X(読みやすいレポート用)、およびプロテクト28X(コーチ共有用)。特定の日付範囲を選択し、含めるメトリクスを選択し、GPS データを含めるかどうかを決定し、iOS 共有シートを介して任意の宛先 (電子メール、クラウド ストレージ、メッセージング アプリ) にエクスポートします。独自の形式やベンダーのロックインもなく、データは移植可能な状態を保ちます。好みのツールを使用して、バックアップ、コーチ共有、または外部分析のためにいつでもエクスポートできます。
